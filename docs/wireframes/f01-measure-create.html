F01 측정 생성 화면 — 와이어프레임

StepMeter 대시보드 UI · 개발계획서 W1 산출물 · 레이아웃 명세는 f01-measure-create.md

이 파일을 읽는 방법
  • 동작하지 않는 정적 목업입니다. 버튼과 입력칸은 그림이고 값은 모두 예시입니다.
  • 숫자(예상 시간·비용·남은 횟수)는 자리를 보여주기 위한 예시값이며 확정된 값이 아닙니다.
  • 상태별로 프레임을 따로 뒀습니다. 실제 화면은 하나이며 조건에 따라 아래 상태로 바뀝니다.
  • 라이트 테마만 그렸습니다. 대비 검토 기준을 하나로 고정하기 위해서입니다.
  • 색·간격·타겟 크기는 shadcn/ui neutral 토큰에 맞췄습니다. 디자인 시스템이 확정되면 그 값을 따릅니다.

리뷰어에게 묻는 것

1
플랫폼 백엔드 · 가장 급함
예상 시간은 화면이 추정하고, 예상 비용은 서버가 주는 방식으로 나눠도 될까요?

받아들여지지 않으면 요약 열 전체가 로딩·실패 상태를 갖는 구조로 다시 짜야 합니다. 구현을 시작하기 전에 답이 필요합니다. 근거는 명세의 "예상 소요 시간·비용 계산 주체 (제안)" 절입니다.

2
에이전트 코어 · 플랫폼 백엔드
답이 나왔습니다. 테스트 계정은 M3 이후에 받습니다. 보관 위치와 기간은 그때 다시 묻겠습니다.

동결된 openapi.yaml의 TaskCreate에 "테스트 계정(credentials_ref)은 암호화 저장소가 정해진 뒤 추가 (10장, M3 이후)"라고 적혀 있습니다. 지금은 화면이 값을 보낼 곳이 없어 입력칸을 비활성으로 두었습니다.

3
플랫폼 백엔드
측정 생성 요청의 필드명과 아래 4가지를 확정해 주실 수 있나요?

입력 필드 6개의 키 이름 / replay_only 플래그의 위치 / 429 응답에 상한값과 초기화 시각이 들어오는지 / 남은 측정 횟수를 어디서 읽는지. 확정 전까지는 목 JSON으로 개발하고, 타입은 손으로 만들지 않습니다. 명세의 "플랫폼 백엔드에 요청할 것" 절입니다.

4
리포트 UI (디자인 시스템)
과업 예시 칩에 공용 컴포넌트를 쓰나요?

쓴다면 칩 높이가 그쪽 값에 따라갑니다. 이 목업은 권장 타겟 44px을 지키려고 44px로 올리고 라벨을 짧게 썼습니다. 공용 컴포넌트가 더 작으면 그 결정을 다시 봐야 합니다.

5
리포트 UI (디자인 시스템)
색 토큰을 어떻게 연결하나요?

이 목업의 색은 shadcn/ui neutral 기준의 임시값입니다. 디자인 시스템이 확정되면 그 색으로 대비를 다시 계산해야 합니다. 특히 조작 요소 경계는 3:1을 넘겨야 합니다.

주석
  1. 1측정할 주소 — 필수. http/https만 받습니다. 형식 검사는 포커스 이탈 시점과 제출 시점에 합니다.
  2. 2과업 — 필수. 예시 3개를 칩으로 제공합니다(기획서 요구). 칩을 누르면 입력칸을 그 문장으로 채우고, 사용자가 이어서 고칠 수 있습니다.
  3. 3성공 조건 — 선택. 비었을 때 에이전트가 과업 문장으로 판단한다는 점을 설명 문구로 밝힙니다.
  4. 4테스트 계정 — M3 이후. 동결된 openapi.yaml의 TaskCreate가 아직 받지 않아 비활성으로 둡니다. 받기 시작하면 리포트·스크린샷에 남기지 않는다는 안내를 입력칸 바로 아래에 두고, 값은 전송 외의 용도로 보관하지 않습니다.
  5. 5화면 크기 — 데스크톱 1280×800 / 모바일 390×844 둘 중 하나. 선택 상태를 테두리 색만으로 알리지 않고 "· 선택됨" 글자를 함께 씁니다.
  6. 6측정 예상 — 숫자 옆에 항상 기준("반복 3회 기준 · 데스크톱")을 씁니다. 모바일을 고르면 예상 시간 영역을 숨기고 그 이유를 한 줄로 씁니다.
  7. 7오늘 남은 측정 — F17 일일 상한. 재생만 하는 측정(replay_only)은 이 숫자에 세지 않으므로, 카운트 규칙을 설명으로 노출합니다.

이 목업에 적용한 자체 UX 기준

  • 텍스트 대비 — 본문 #0a0a0a 19.80:1, 보조 설명 #525252 7.81:1, 오류 #b91c1c 6.47:1. 모두 4.5:1 이상입니다.
  • 조작 요소 경계 대비 — 입력칸·버튼·라디오·칩·고급 설정 테두리는 #737373으로 흰 배경 4.74:1, #f5f5f5 위 4.35:1입니다. 3:1 이상입니다.
  • 장식 구분선 — #d4d4d4는 1.48:1로 3:1에 못 미칩니다. 영역을 나누기만 하고 조작할 수 없는 선(헤더 밑줄, 카드 테두리, hr)에만 썼습니다. WCAG 1.4.11은 순수 장식 요소를 적용 대상에서 제외합니다. 조작할 수 있는 요소에는 이 색을 쓰지 않습니다.
  • 타겟 크기 — 버튼·입력칸·내비 항목·과업 예시 칩 모두 44px 이상입니다. 칩은 라벨을 짧게 써서 44px로 올리고도 한 줄을 유지합니다. 권장치 미달 요소는 없습니다.
  • 이름 없는 요소 0건 — 아이콘만 있는 요소(좁은 화면 메뉴 버튼)에 aria-label을 넣었습니다.
  • 색만으로 의미를 전달하지 않습니다 — 오류는 ▲ 기호와 문장, 선택 상태는 "· 선택됨" 글자, 비용 증가는 "(3회 대비 +$0.12)" 문구를 함께 씁니다.
  • 숫자 옆에 기준을 씁니다 — "약 4분 30초 / 반복 3회 기준 · 데스크톱", "약 $0.30 / LLM 호출 추정".
