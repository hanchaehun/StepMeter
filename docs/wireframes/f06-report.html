StepMeter 리포트 UI · 개발계획서 W1 산출물 · 레이아웃 명세는 f06-report.md · 참고 리포트 분석은 report-reference.md

이 파일을 읽는 방법
  • 동작하지 않는 정적 목업입니다. 행·점·버튼·링크는 그림이고, 상태별로 프레임을 따로 뒀습니다. 실제 화면은 리포트 요약과 단계 상세 둘입니다.
  • 값은 전부 동결된 목 JSON(tests/fixtures/mock/api/report.json, steps.json)에서 가져왔습니다. 스크린샷만 진짜 캡처가 없어 CSS로 그린 가짜 쇼핑 페이지입니다.
  • 서비스 기획서 6.1 그대로 "리포트 요약"과 "단계 상세" 두 화면입니다. 두 이름이 22px 제목 줄에 나란히 보이고, 문제 행·시도 점을 누르면 단계 상세로, "리포트 요약" 또는 뒤로가기로 돌아옵니다.
  • 라이트 테마만 그렸습니다. 색·간격·타겟 크기는 F01 명세의 토큰을 그대로 채택했습니다(F01 질문 5번에 대한 답).

주석
  1. 1
    세로 스크린샷은 영역 가운데에 높이 기준으로 맞춘다. 양옆 여백은 #f3f4f6. 엄지 도달 구역 표시(기획서 F08)는 데이터 출처가 정해지면 이 스크린샷 위에 반투명 띠로 그린다(묻는 것 1번).
  2. 2
    모바일은 est_seconds·est_task_time이 null이라 예상 시간 칩을 빼고, Overview의 Verdict와 Path metrics에서도 예상 소요 시간 자리를 "데스크톱에서만 계산"으로 바꾼다. slowest_steps는 빈 배열.

이 목업에 적용한 자체 UX 기준

  • 텍스트 대비 — 본문 #0a0a0a 19.80:1, 보조 #525252 7.81:1, 꼬리말·라벨 #737373 4.74:1, 오류 #b91c1c 6.47:1, 통과 표시 #166534 7.06:1. 모두 4.5:1 이상.
  • 조작 요소 경계 — 화면 전환 링크 밑줄, 단계 버튼, 아이콘 버튼은 #737373 또는 #171717. 3:1 이상. 행 구분 hairline #e5e5e5와 #d4d4d4는 장식 전용이고 조작 요소에 쓰지 않는다.
  • 타겟 크기 — 화면 전환 링크, 행(높이 70px 이상), Attempts 점(36px 버튼, 간격 14px → 유효 50px), 단계 버튼, 아이콘 버튼 모두 44px 이상. 점만 36px인데 WCAG 2.5.8의 간격 예외(인접 타겟과 24px 원이 겹치지 않음)를 만족한다. 권장 44px에 맞추려면 점 버튼을 44px로 키워도 레이아웃이 깨지지 않는다.
  • 색만으로 의미를 전달하지 않는다 — 심각도는 ▲(High) ■(Medium) ●(Low) 기호 + 영어 글자. 문제 있는 단계는 빨간 테두리 점 + "⚠ 문제 1" 글자 + 범례. 재생 끊김은 ◆ + "Step 1에서 끊김".
  • 숫자 옆에 기준 — "2.9 : 1 · 기준 4.5 : 1 (WCAG AA)", "30px · 권장 44px (최소 24px)", "7.9초 (문헌값 기준)", "편차 ±12% · 추정 약함".
  • 이름 없는 요소 0건 — 아이콘 버튼(◀ ▶ ✕)과 Attempts 점에 aria-label. 스크린샷 오버레이는 장식이라 aria-hidden, 같은 정보를 오른쪽 글로 제공.
  • 화면 전환 — 단계 상세로 가면 "단계 상세" 제목(tabindex=-1)에 포커스를 옮겨 스크린 리더·키보드 사용자에게 전환을 알린다. 뒤로가기는 요약으로 돌아온다(pushState 1회).
  • 자기 측정 — W4부터 "측정 생성 → 리포트 확인" 과업을 StepMeter로 재서 대비 부족·작은 타겟·이름 없는 요소 0건을 확인한다.
