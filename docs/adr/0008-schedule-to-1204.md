# 0008. 최종 발표를 12/4로 당기고 일정과 범위를 줄인다

- **날짜:** 2026-11-05 (PM 결정)
- **근거 기록:** 2026-11-05 PM 일정 변경 결정. 개발계획서 14장의 일정을 대체한다

## 배경

개발계획서는 10/26부터 12/20까지를 W1~W8로 나누고, 12/6에 기능을 동결한 뒤 W7에 홀드아웃 앱을 평가하고 W8에 최종 평가를 발표하기로 했다.
학회 일정상 최종 발표가 12/4로 확정됨(11/5 통보). 발표가 12/20에서 12/4로 당겨져 W7·W8이 없어지고 W6도 12/4에 끝난다. 남은 기간에 맞춰 일정과 범위를 다시 정한다.

## 결정

주 단위 일정은 아래와 같다. W7·W8은 없다.

| 주 | 기간 | 비고 |
|---|---|---|
| W1 | 10/26–11/1 | |
| W2 | 11/2–11/8 | M2 |
| W3 | 11/9–11/15 | |
| W4 | 11/16–11/22 | M3 |
| W5 | 11/23–11/29 | M4 (11/27 기능 동결) |
| W6 | 11/30–12/4 | 마지막 주 |

바뀐 날짜와 규모는 아래와 같다.

| 항목 | 이전 | 변경 |
|---|---|---|
| 기능 동결 (M4) | 12/6 | 11/27(금) |
| 홀드아웃 앱 최종 평가 | W7 | 11/30–12/1. 회귀 비교·인프라 담당 혼자 1회 돌린다 |
| 모델 테스트 세트 평가 | W7 | 11/30–12/1 |
| 데모 영상·발표 자료 | 12월 셋째 주 | 12/2–12/3 |
| 최종 발표 | 12/20 | 12/4 |
| 외부 사용자 테스트 | W5·W6, 3~5팀(목표 5팀) | 11/18–11/26, 3팀. 팀 확정 11/13. 피드백은 11/27 동결 전에 반영한다 |
| 실사이트 판정 | 약 60건 | 약 20건 |

외부 사용자 테스트: 1차는 M3 전 화면으로 진행한다. 11/26 이후 들어온 피드백은 버그만 W6에 고치고 나머지는 발표의 향후 과제로 넣는다.

범위는 아래처럼 줄인다.

- F14 CI 연동은 이번 범위에서 뺀다.
- 테스트 계정은 이번 일정에서 구현하지 않는다([ADR 0004](0004-test-account-after-m3.md)).
- 모바일 뷰포트, KLM 보정 완성, 로지스틱 회귀 ablation은 선택 항목이다.
- 사람 실험은 그대로 진행한다. 시간이 부족하면 KLM 보정을 마치지 않고 사람 측정값과 예측값 비교만 발표에 넣는다.

기획서(docs/*.docx)는 고치지 않는다. 기획서와 다르면 이 ADR을 따른다.
동의서의 보관 종료일 2026년 12월 31일은 그대로 둔다.
`apps/api/openapi.yaml`의 `RunMode` 설명에 남은 "CI용"과 F14는 이번 변경에서 고치지 않는다. 이 파일에서 생성하는 `apps/web/src/api/types.ts`와 `apps/api/db/db-columns.md`의 `mode` 설명도 그대로 둔다.

## 대안

- 범위를 그대로 두고 기간만 줄인다: W7·W8 작업을 W6 안에 넣고, 외부 사용자 테스트 5팀과 실사이트 약 60건 판정도 같은 기간에 끝내야 한다.
- 기능 동결을 12/6으로 둔다: 최종 발표(12/4)보다 늦다.
