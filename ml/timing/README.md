# ml/timing/

- **담당 역할:** 측정 지표·규칙
- **하는 일:** 소요 시간 모델 (문헌 KLM + 보정 계수). 사람 실험은 IRB 심의 없이 동의서를 받아 진행한다([ADR 0001](../../docs/adr/0001-no-irb.md)). 사람 데이터로 보정하지 못하면 문헌값만 쓰며 리포트에 '보정'이라고 표시하지 않는다. 사람 실험은 그대로 진행하고 KLM 보정 완성만 선택 항목이다. 시간이 부족하면 사람 측정값과 예측값 비교만 발표에 넣는다([ADR 0008](../../docs/adr/0008-schedule-to-1204.md)).
- **참고:** 개발계획서 5.10, 9.1

## ADR 0011에 따른 할 일

- 과업 시간을 어디서 어디까지로 볼지는 결과를 보기 전에 이 문서에 적는다 (ADR 0011 3번)
- 보정 계수와 Fitts 식 대체는 선택이다 (ADR 0011 3번)

- 화면 안정 시점은 click·key 뒤에 처음 나온 `stable`만 쓴다. 다음 행동 전까지 더 나온 `stable`(마우스를 올려 생긴 것 포함)은 쓰지 않는다. 생각 시간(M) 표본과 R 구간 계산에 같은 기준을 쓴다 (ADR 0011 3번)

PR #46에서 요청한 시작·종료 시점, R 제외, 누락 클릭 처리의 사전 정의다.

`session.py`, ADR 0011 및 PR #46 C-4 절차를 확인해 작성했다.
2026-11-13 PM 확정. 홀드아웃·본 분석이 끝날 때까지 바꾸지 않는다.
수집 코드·공유 스키마 변경은 포함하지 않는다.

### 1. 시작과 종료

- 시작 `t_start`: 세션의 첫 `stable.t_ms`. 페이지 표시를 로그로 근사한 값이다.
  `started_at`은 브라우저 실행 전 시각이므로 시작점으로 쓰지 않는다.
  `stable`은 load 및 DOM 변경 뒤 300ms 안정화 조건을 포함하며 정확한 화면 표시 시각은 아니다.
- 첫 stable 전에 click/key/down/up/scroll이 있으면 이미 조작을 시작한 기록이므로
  시작점 불명으로 표시하고 주 분석에서 제외한다. move만 있는 경우는 제외하지 않는다.
- 성공 판정: 진행자가 PR #46 C-4의 완료 상태를 확인하고 `completed=true`로 저장한 세션.
- 종료 `t_end`: C-4 완료 상태를 유발한 마지막 유효 행동의 시각이다.
  포인터는 click(보완 시 up), 키보드 조작은 key를 사용한다.
  완료 화면이 뜨는 시각, 진행자의 Enter, 마지막 move/scroll/stable은 종료 기준으로 쓰지 않는다.
  마지막 행동 이후의 화면 응답과 진행자 반응 지연은 이 정의에서 이미 제외된다.

| 과업 | C-4 완료 상태 | 종료 행동의 기준 |
|---|---|---|
| 회원가입 | 로그인 화면으로 이동 | Register Account 실행 |
| 비밀번호 표시 | 비밀번호가 보임 | 표시 전환 컨트롤 실행 |
| Tasks | TASK-8202 Edit 화면 열림 | 해당 작업의 Edit 실행 |
| 제품 정렬·필터 | 정렬 설정 후 Apparel 선택 | Apparel 선택 |
| Remember Me | 입력 후 체크됨 | Remember Me 선택 |
| 사용자 초대 | 제출 알림 표시 | Invite 실행 |

`target_key`는 요소 지문이며 URL·행 번호·선택 상태를 모두 담지는 않는다.
현재 파일에는 완료 이벤트, Enter 시각, 누른 키 값도 없다. 따라서 단순히 마지막
key/click을 골라 성공 행동이라고 확정하지 않는다. 완료 여부·대상 지문·이벤트 순서와
진행 메모가 일치할 때 종료 행동을 지정한다. 완료 후 추가 조작, 중복 지문, 키보드
완료 등으로 식별이 불가능하면 `end_unresolved`로 남겨 주 분석에서 제외하고 건수를 보고한다.
원본 이벤트 인덱스와 선택 근거를 분석 결과에 남긴다.

2026-11-13부터 진행자는 과업 문장을 창을 띄우기 전에 읽는다(`human-study/session-procedure.md`, PR #46).
그 전 세션은 읽어 주는 시간이 포함될 수 있어, 해당 참가자 코드(팀원 전용 Notion에 표시)는 따로 보고하고
주 분석 포함·제외 결과를 함께 낸다.
`completed=false`(시간 초과·중단 포함)는 성공 시간 중앙값에서 제외하고 별도 건수로 보고한다.

### 2. click 누락 시 down/up 보완

원본 JSON은 그대로 보존하고 분석용 이벤트 목록에서만 보완한다.

1. 파일 순서를 유지해 down과 그 뒤 첫 up을 짝짓는다. 사이에 새 down이 나오면
   앞 down은 미완성으로 남긴다. 동일 시각 이벤트도 원본 인덱스로 구분한다.
2. up 이후 다음 down/key/scroll 전에 500ms 이내, up에서 5 CSS px 이내의
   실제 click이 있으면 해당 click을 사용하고 보완하지 않는다. 중복 후보는 확인 필요다.
3. 실제 click이 없고 down→up 시간이 0~1000ms이며, down부터 up까지 기록된
   모든 포인터 위치가 down에서 5 CSS px 이내이고 key/scroll이 끼지 않으면
   up 시각에 클릭 1건을 보완한다. 짝 없는 up, 좌표 누락, 범위 초과는 자동 보완하지 않는다.
4. 대상은 up.target_key를 우선한다. up이 null이고 down에 대상이 있으면 down의
   지문을 사용하되 `target_from_down`으로 표시한다. 둘 다 있고 다르면 자동 보완하지 않는다.
   둘 다 null이면 대상 미상으로 보존하며 완료 행동을 확인한 것으로 취급하지 않는다.
5. 보완 여부, down/up 원본 인덱스, 선택 대상의 출처를 기록한다.

500ms·1000ms·5px는 ADR에 정해진 값이 아닌 보수적인 매칭 상수다.
2026-11-13 PM 확정. 홀드아웃·본 분석이 끝날 때까지 바꾸지 않는다.
현재 이벤트에는 pointer ID·마우스 버튼·pointercancel 정보가 없어 완전한
복원이 불가능하다. 애매한 조작을 성공 클릭으로 자동 분류하지 않는다.

#### 2절 구현: ml.timing.human

- 함수: `ml.timing.human.click_events(events)` (원본 `events`는 바꾸지 않는다)
- 기준: 위 2절(1~5번)을 그대로 따른다(별도 규칙 없음). 시각 역행·비정상 값은 `ValueError`를 낸다.
- 반환 형식: `list[dict[str, Any]]`. 각 원소는 `t_ms`, `type` (`"click"`), `x`, `y`, `target_key`와
  `supplemented` (`bool`), `down_index` (`int | None`), `up_index` (`int | None`),
  `click_index` (`int | None`), `target_source` (`"click" | "up" | "target_from_down" | "unknown"`)를 담는다.

### 3. 응답 대기 R 추정과 제외

ADR 0011에 따라 click/key(위에서 보완한 클릭 포함) 뒤 첫 stable만 사용한다.
이를 **화면 안정 기반 대기 추정**으로 부르며 실제 네트워크 지연과 같다고 해석하지 않는다.

- 행동 a 뒤 첫 stable s가 다음 click/key/down/up/scroll보다 먼저 있고,
  `t_start <= a.t_ms < s.t_ms <= t_end`이면 `[a.t_ms, s.t_ms]`를 후보 구간으로 삼는다.
  같은 시각에 다음 조작과 stable이 있으면 보수적으로 제외한다.
- 실제 click과 짝인 down/up은 같은 조작으로 먼저 묶어 중복 처리하지 않는다.
  다음 조작이 먼저 오면 앞 행동의 대기는 미확정으로 남긴다. 연속 타이핑은 마지막
  key 뒤 첫 stable이 다음 조작 전에 있는 경우만 인정한다.
- move는 응답 종료 사건으로 쓰지 않는다. 다만 hover로 발생한 stable도 로그만으로
  구별할 수 없어서 첫 stable 자체가 오인될 가능성은 남는다.
- 그 뒤 다음 행동 전까지 발생한 추가 stable은 무시한다. 대응 stable이 없으면
  추정 구간을 만들지 않고 미확정 건수를 남긴다(실제 대기가 0이라는 뜻은 아니다).
- 후보 구간의 합집합 길이를 한 번만 빼며, 분석 범위 밖 구간은 사용하지 않는다.
  종료 행동 뒤 응답은 종료 정의에서 이미 빠졌으므로 다시 빼지 않는다.
- 수집기의 300ms 안정화 지연은 포함된 채 사용한다. 실제 지연을 알 수 없으므로
  모든 구간에서 일률적으로 300ms를 빼지는 않는다. 과다 제외 가능성을 한계로 명시한다.

```text
T_observed = (t_end - t_start) / 1000
R_estimated = 대기 후보 구간 합집합의 길이 / 1000
T_adjusted = T_observed - R_estimated
```

예시(합성 기록): 첫 stable 1.0초, 클릭 3.0초, stable 3.8초,
추가 stable 4.2초, 완료 클릭 6.0초, 마우스 이동 7.0초이면
T_observed=5.0초, R_estimated=0.8초, T_adjusted=4.2초다.
3.8초 전에 다음 조작이 있었다면 3.0초 행동의 후보 구간은 채택하지 않는다.

두 시간(T_observed, T_adjusted)과 제외 구간·미확정 건수를 모두 남긴다.
주 비교는 성공하고 시작·종료를 식별한 세션의 페이지별 T_adjusted 중앙값과
같은 과업 run의 est_task_time이다. T_observed 비교도 함께 보고해 R 제외의 영향을 보인다.
미확정 구간이 있는 세션은 표시하고, 해당 세션 포함/제외 결과와 표본 수를 함께 보고한다.
음수 시간·시각 역행·시작 또는 종료 누락은 0으로 보정하지 않고 검증 오류로 처리한다.
