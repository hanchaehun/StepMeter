# 사람 실험 파일 수령 절차

기준: ADR 0011 4번, human-study/session-procedure.md D절 및 진행 프로그램 방식.
실험은 계속 진행해도 되며, 끝난 참가자의 자료부터 전달할 수 있다.

## 운영 담당 → 측정 지표 담당

1. 진행 프로그램이 만든 참가자별 `upload-<코드>.zip`을 팀원 전용 Notion 페이지에 올린다.
   세션 JSON만 따로 추리지 않고 notes·검사 결과 등 프로그램이 묶은 자료를 유지한다.
2. 페이지 소유자가 측정 지표 담당 계정에 접근 권한을 주거나, 해당 계정이 접근 가능한
   팀원 전용 페이지로 전달한다. 공개 링크·저장소·이슈·메신저에 자료를 올리지 않는다.
3. 측정 담당은 동기화되지 않는 로컬 보관 폴더에 내려받는다. git 제외 경로라도
   Documents/바탕 화면이 OneDrive 동기화 대상이면 사용하지 않는다.
4. 참가자 코드별 6페이지 파일·notes·검사 결과를 확인한다. 오류/invalid 기록과
   누락 페이지는 임의 수정하지 않고 운영 담당에게 확인한다. 기존 check_sessions.py의
   오류·경고 기준과 실행 방법은 human-study/session-procedure.md를 따른다.
5. notes의 수집 방식·app_version·사이트 빌드 해시·완료 확인·중단/기술 문제를 보존한다.
   이전 절차 여부와 분석 제외 기준은 ml/timing/README.md를 따르고,
   원본을 덮어쓰거나 경고를 성공으로 바꾸지 않는다.
6. 참가자 철회 또는 2026-12-31 보관 기한에 맞춰 진행자/분석 PC 사본과 zip,
   Notion 첨부·휴지통을 모두 삭제한다. 서명 동의서는 자료와 분리한다.

## 현재 확인 범위

GitHub 절차서에서 참가자별 zip·전달 경로·보관/삭제 규칙은 확인했다.
이 작업에서는 실제 참가자 자료를 열거나 분석하지 않았다.
팀원 전용 Notion 페이지의 접근 권한과 실제 첨부 상태는 확인되지 않았다.
수령자가 해당 워크스페이스에 접근할 수 없어 페이지 소유자의 공유 설정이 필요하다.
비공개 페이지 주소와 참가자 정보는 이 문서에 적지 않는다.
