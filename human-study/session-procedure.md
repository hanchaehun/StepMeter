# 사람 실험 세션 진행 절차

참가자 한 명의 세션을 처음부터 끝까지 진행하는 방법이다. **이 문서 하나만 보고 진행할 수 있게 썼다.**
진행자가 참가자에게 하는 말은 인용 상자(>)의 문장을 그대로 읽는다. 진행자마다 설명이 달라지면 측정값도 흔들린다.

- **담당:** 대시보드 UI (세션 운영)
- **상태:** 안. 파일럿 3명을 마친 뒤 확정한다.
- **배경 문서(읽지 않아도 진행 가능):** [동의서](consent-form.md), [6페이지와 과업 문장](pages.md), [수집 스크립트 설명](README.md), [진행 프로그램](app/README.md)

## 진행 방식: 참가자가 노트북을 직접 쓴다 (`self_guided_v1`, 2026-11-14부터)

진행자는 조건 확인(C-1)과 동의서(C-2)까지 하고 **노트북을 참가자에게 건넨다.** 참가자는 진행 프로그램 화면에 나온
안내와 과업 문장을 직접 읽고, 과업마다 [시작]을 눌러 브라우저 창을 열고, 끝나면 화면 오른쪽 패널의 [다 했어요] 또는
[그만할게요]를 누른다. 진행자는 옆에서 보기만 하고, 참가자가 노트북을 돌려주면 페이지별 완료 여부를 확정하고 진행 이상을
메모한다(C-5).

- 3분 제한·저장·세션 직후 검사·업로드 zip은 프로그램이 한다. 스톱워치는 필요 없다.
- 참가자 화면에는 결함, 끝난 시점, 남은 시간이 나오지 않는다.
- 수집하는 세션 json 형식은 그대로다(`session.py`). 진행 방식은 notes의 `procedure_version`(`self_guided_v1`)에 남는다.
  그 전 세션은 진행자가 과업 문장을 읽어 주는 방식이었다(`read_aloud`, 이 문서의 git 기록 참고). 프로그램 전에 진행한
  세션은 처음 화면의 [이미 끝난 세션 메모 입력]으로 페이지별 진행 이상을 남긴다.
- 프로그램을 쓸 수 없으면 세션을 열지 않고 세션 운영 담당에게 알린다.

## A. 처음 한 번: 진행 프로그램 받기

### A-1. Windows

세션 운영 담당이 전달한 `StepMeter-human-<버전>.zip`을 풀고, 폴더 안의 `StepMeter-human.exe`를 더블클릭한다.
설치·저장소·명령이 필요 없다(사이트·수집 스크립트·브라우저가 폴더 안에 있다). 처음 실행 때 파란 "Windows의 PC 보호" 창이
뜨면 "추가 정보 → 실행"을 누른다. 폴더는 통째로 두고 쓴다.

### A-2. Mac

저장소를 받은 뒤 Finder에서 `human-study/app/run_mac.command`를 더블클릭한다. Python 3.12와 Node 22가 있어야 한다.
처음 한 번은 설치·사이트 빌드로 10~15분 걸리고, 각 단계가 실패하면 무엇을 하면 되는지 창에 나온다.

### A-3. 화면 크기

브라우저 창(1280×800 페이지 + 브라우저 UI 약 100px)과 오른쪽 참가자 패널이 겹치지 않고 다 보여야 한다. 창이 잘리면
참가자가 보는 첫 화면이 기록과 달라져 첫 화면 판정(R06)이 틀어진다. 프로그램의 시작 전 점검이 확인하고, 모자라면 시작이 막힌다.

- Windows: 설정 → 디스플레이 → 배율을 **100%로** 낮춘다(FHD 125%는 세로 864px라 모자란다).
- Mac: 시스템 설정 → 디스플레이 → **'더 넓게'**를 고른다. '더 넓게'로도 가로가 1700px이 안 되는 기종이 있다.
- **첫 세션 전에** 내 노트북에서 연습 모드로 [점검하기]까지 해 본다. 배율을 바꿔도 화면 높이·너비가 실패하면 그 노트북으로는
  세션을 열지 않고 세션 운영 담당에게 알린다.

## B. 세션 날 시작

1. 프로그램을 연다. 사이트 서버는 프로그램이 띄운다(이 PC에서만 열린다).
2. 진행자(이 PC에 기억된다. 목록에 없으면 "기타"와 GitHub 아이디), 참가자 코드(내 범위의 다음 빈 번호가 자동으로 나온다)를
   확인하고 [다음: 시작 전 점검].
3. 마우스를 연결하고 체크한 뒤 [점검하기]. 사이트 6개 주소, 사이트 빌드(결함판 확인을 통과한 빌드인지), 수집 스크립트,
   화면 높이·너비, 저장 폴더를 확인한다. 하나라도 실패하면 [시작]이 막힌다. 실패 이유대로 고치고 [다시 점검].
   "예전 저장 위치"가 실패하면(2026-11-15 판 exe를 쓴 PC) 나온 폴더의 파일을 모두 새 저장 폴더로 옮긴다.
   사이트 빌드가 실패하면 그날 세션을 열지 않고 세션 운영 담당에게 알린다.
- 리허설·연습은 "연습 모드"(코드 `P00`, 연습 폴더에 따로 저장)로 한다.

## C. 참가자 세션

### C-1. 참가 조건 확인 (진행자 화면, 과업 설명보다 먼저)

> "시작하기 전에 하나만 여쭤볼게요. 관리자 대시보드나 로그인 화면 같은 웹 화면 몇 개를 쓰실 텐데, 혹시 SB Admin, Material Kit, shadcn admin 같은 관리자 템플릿 화면을 전에 써 보신 적 있으세요?"

- "있다"면 그 자리에서 끝내고 데이터를 받지 않는다:
  > "이번 연구는 처음 보시는 분의 기록이 필요해서요. 시간 내 주셔서 감사합니다."
- 과업 설명을 들은 뒤에는 "본 적 있다"고 말하기 어려워지므로 이 질문을 맨 먼저 한다. [중단]을 누르면 데이터도 코드도 남지 않는다.

### C-2. 동의서와 참가자 코드 (진행자 화면)

1. 동의서를 건네고 읽을 시간을 준다. 3·4절(기록하는 것, 기록하지 않는 것)을 짚어 준다:
   > "입력하신 글자는 저장하지 않고, 키를 누른 시각만 남습니다."
2. 질문을 받고 서명을 받는다. 서명하지 않으면 진행하지 않는다.
3. 참가자 코드를 정한다(프로그램이 제안한다).
   - 형식은 `P01`, `P02`, … 이다. **진행자끼리 겹치면 안 되므로** 아래 표의 내 범위 안에서 작은 번호부터 순서대로 쓴다. 범위를 다 쓰면 세션 운영 담당에게 더 받는다. 범위 밖 번호는 프로그램이 확인을 받는다.

     | 진행자 | 참가자 코드 |
     |---|---|
     | @bomink1215 | `P01` – `P04` |
     | @hanchaehun | `P05` – `P07` |
     | @doithyun | `P08` – `P09` |
     | @leewonjunlee-eng | `P10` – `P11` |
     | @bshyuunn | `P12` – `P13` |
     | @msterk11 | `P14` |

   - 조건 확인에서 돌려보낸 사람이나 동의하지 않은 사람에게는 코드를 주지 않는다. 코드는 동의서에 서명한 참가자에게만 쓴다.
   - 리허설·연습에는 `P00`만 쓴다(연습 모드). 본 데이터와 섞이지 않게 하기 위해서다.
   - 동의서에는 코드를 적는다. 이름과 코드를 잇는 표는 **만들지 않는다**. 이름·연락처를 어디에도 적지 않는다.

### C-3. 노트북 건네기 (진행자 화면 → 참가자에게)

화면에 "노트북을 참가자에게 건네주세요"가 나오면, 건네며 이렇게 말하고 [건넸어요]를 누른다:

> "이제부터는 노트북 화면에 나오는 안내대로 혼자 해 주시면 됩니다. 마우스를 써 주세요. 과업마다 브라우저 창이 새로 열리는데, 그 창은 닫지 말아 주세요. 과업을 마치면 오른쪽의 [다 했어요]를, 그만하고 싶으면 [그만할게요]를 눌러 주세요."

건넨 뒤에는 옆에서 **보기만 한다.**

- 참가자가 물으면 이렇게만 답한다. 과업 문장을 풀어 설명하거나 화면을 가리키지 않는다:
  > "화면에 있는 문장대로 해 주세요."
- **어느 페이지에 결함이 있는지 말하지 않는다.**
- 브라우저 창을 대신 닫거나, 버튼을 대신 누르지 않는다. 참가자가 창을 닫으면 그 페이지는 미완료로 저장되고 다음 과업으로 넘어간다.
- 도움을 요청받아 답했거나 이상한 일이 있었으면 기억해 두었다가 C-5 확인표에 적는다.

### C-4. 과업 6개 (참가자 화면)

참가자 화면에는 아래 문장만 나온다(진행자가 읽지 않는다).

| 화면 | 문구 |
|---|---|
| 시작 안내 | 아래 "시작 안내" |
| 과업마다 | "과업 n / 6", (④만 데모 안내), 과업 문장, (①만 입력할 값), "읽으셨으면 [시작]을 눌러 주세요." → [시작] |
| 진행 중 | 화면 오른쪽 패널에 같은 과업 문장(①은 값도)과 "브라우저 창은 닫지 말아 주세요.", [다 했어요] [그만할게요] |
| 3분이 되면 | 소리와 함께 "여기까지 하셔도 됩니다." → [다음] (미완료로 저장) |
| 창을 닫으면 | "브라우저 창이 닫혔습니다. 다음 과업으로 넘어갈게요." → [다음] (미완료로 저장) |
| 브라우저가 멈추면 | "브라우저에 문제가 생겼습니다. 다음 과업으로 넘어갈게요." → [다음] (미완료로 저장) |
| 6개가 끝나면 | "수고하셨습니다. 노트북을 진행자에게 돌려주세요." → [돌려줬어요] (진행자가 누른다) |

참가자 화면 문구(글자 그대로):

- 시작 안내:
  > "웹 페이지 6개에서 간단한 일을 하나씩 해 주세요. 빨리 하거나 잘할 필요는 없습니다. 막히면 끝내지 못하셔도 괜찮습니다. 입력 칸에는 화면에 나온 가짜 값만 넣어 주세요."
- 사용 시간(참가자가 직접 입력):
  > "평소에 컴퓨터를 하루 몇 시간쯤 쓰세요? 대략이면 됩니다(0~24, 숫자만)."
- 과업 화면:
  > "읽으셨으면 [시작]을 눌러 주세요."
- 진행 중 패널:
  > "브라우저 창은 닫지 말아 주세요."
- 3분:
  > "여기까지 하셔도 됩니다."
- 창 닫힘:
  > "브라우저 창이 닫혔습니다. 다음 과업으로 넘어갈게요."
- 브라우저 오류:
  > "브라우저에 문제가 생겼습니다. 다음 과업으로 넘어갈게요."
- 끝:
  > "수고하셨습니다. 노트북을 진행자에게 돌려주세요."

과업 문장을 읽은 뒤 참가자가 [시작]을 눌러야 창이 열리므로, 과업 시간에 문장을 읽는 시간이 섞이지 않는다. 기록은 페이지가 처음 뜬 시점부터다.
3분은 페이지가 뜬 때부터 잰다. 남은 시간은 참가자에게 보이지 않는다.

**순서는 아래로 고정한다.** 비슷한 로그인 과업인 3번과 4번 사이에 다른 과업 두 개를 둬서 학습 효과를 줄였다.

| 차례 | ① | ② | ③ | ④ | ⑤ | ⑥ |
|---|---|---|---|---|---|---|
| 과업 # | 1 | 3 | 5 | 2 | 4 | 6 |

- **같은 참가자가 같은 페이지를 두 번 하지 않는다.** 프로그램이 막는다. 프로그램이 중간에 꺼지면 다시 열어 같은 코드로
  이어 한다(저장된 페이지는 건너뛴다).

아래 과업 문장은 [pages.md](pages.md), `benchmark/tasks.json`(에이전트 과업), `session_plan.json`(프로그램)과 글자 그대로 같다(ADR 0011 1번).
"끝난 시점"은 진행자만 보는 기준이다(C-5 확인표에 나온다).

> "이 페이지는 데모라 정렬이나 필터를 바꿔도 목록은 바뀌지 않습니다."

> "정렬을 Price: Low-High로 바꾸고, 필터에서 Category를 Apparel로 골라 주세요."

- **끝난 시점:** Category에서 Apparel이 선택됨(목록은 바뀌지 않는다)

### C-5. 페이지별 확인표 (진행자 화면, 노트북을 돌려받은 뒤)

참가자가 노트북을 돌려주면 [돌려줬어요]를 누른다. 6페이지마다:

1. **완료 확정:** 기본값은 참가자 답이다([다 했어요] = 완료, [그만할게요] = 미완료). 옆에 나온 "끝난 시점"을 실제로 봤는지에
   따라 확정한다. 3분 종료와 창 닫힘은 미완료로 고정이다. 바꾸면 그 페이지 세션 파일의 `completed`만 고쳐 다시 저장되고,
   원래 값과 바꾼 사실이 notes에 남는다.
2. **진행 이상:** 해당하는 것을 모두 체크하고, 필요하면 한 줄 메모를 쓴다. 이름·연락처는 적지 않는다.
   1 참가자가 진행자에게 도움을 요청해 답해 줌 · 2 참가자가 과업을 잘못 이해함 · 3 버튼을 늦게/일찍 누름 · 4 기술 문제 · 5 기타(메모 필수)

notes에서 진행 이상이 있는 페이지는 그 페이지만 주 분석에서 빠진다([ml/timing/README.md](../ml/timing/README.md)).

### C-6. 끝 (진행자 화면)

> "끝났습니다. 참가자 코드는 P01입니다. 나중에 기록을 지우고 싶으시면 이 코드를 알려 주시면 됩니다."

코드를 종이에 적어 드린다(동의서 6절).

### C-7. 바로 검사 (참가자가 간 뒤, 다음 참가자 전에)

[검사하고 zip 만들기]를 누르면 `check_sessions.py`를 돌려 결과를 보여 주고 `check-<코드>.txt`로 저장한 뒤,
`upload-<코드>.zip`(세션 json 6개 + notes + 검사 결과)을 만들고 폴더를 연다. 출력 예:

```
  sb-admin-2/register/baseline             완료     42초  클릭 3
  material-kit-react/products/baseline     완료     55초  클릭 6
  ...
  6페이지 합계 5.3분 (동의서·안내 시간 제외)
경고: …
오류: …
정상
```

| 보는 곳 | 기준 | 다를 때 |
|---|---|---|
| 마지막 줄 | `정상` | `오류 N건`이면 **파일을 지우지 말고** 수집 스크립트 담당(리포트 UI)에게 출력 전체를 보낸다. 단, 화면에 "세션 파일이 없는 페이지" 안내가 나온 페이지(오류로 건너뜀·프로그램이 중간에 꺼짐)의 "빠짐" 오류는 예상된 것이다. 확인표에 기술 문제로 남았으면 그대로 올리고, 그 밖의 오류가 없으면 알리지 않아도 된다 |
| 페이지별 완료/미완료 | C-5에서 확정한 것과 같다 | 다르면 함께 알린다 |
| 6페이지 합계 | 동의서·안내를 더해 20분 안 | 파일럿이면 기록해 둔다 |

오류로 나오는 것: 6페이지 중 빠진 파일·같은 페이지 파일 2개 이상, 목록에 없는 `page_id`, 스키마 오류·`*.invalid.json`,
뷰포트가 1280×800이 아님, 이벤트 없음, 시각(`t_ms`) 역행.

경고만 나오는 것: **3분 넘은 페이지**(제한 시간에 끊었으면 괜찮다), **대상이 null인 클릭**(본문 글자나 빈 곳을 누른 것이면
괜찮다. 과업 대상 — Register Account, 비밀번호 표시 아이콘, Todo, Edit, Apparel, Remember Me, Invite User, Admin, Invite 등 —
을 누른 클릭이면 수집 스크립트 담당에게 알린다).

### C-8. 참가자가 그만두겠다고 하면 (참가 철회)

동의서 6절("그만두시면 그때까지의 기록을 지웁니다")대로 그때까지의 기록을 지운다. 이유를 묻지 않는다.

1. 과업 진행 중(오른쪽 패널)이면 패널의 [그만할게요]를 진행자가 눌러 그 페이지를 먼저 끝낸다.
2. 진행자 화면이면 [참가 철회 — 기록 지우기]를 누른다. 참가자 화면(시작 안내·과업 문장 등)이면 창을 닫고 프로그램을 다시
   연 뒤 같은 진행자·코드로 [다음] → 시작 전 점검 화면의 [참가 철회 — 기록 지우기]를 누른다.
3. 프로그램이 이 코드의 세션 json·notes·검사 결과·zip을 모두 지우고 `withdrawn-<코드>.txt`(날짜만 적힘)를 남긴다.
   동의서에 이미 그 코드가 적혀 있으므로 **이 코드는 다른 참가자에게 다시 주지 않는다**(프로그램이 막는다).
4. 세션이 끝난 뒤 코드를 알려 와 철회하는 경우도 같다. 세션을 한 PC에서 그 코드로 [다음] → [참가 철회 — 기록 지우기].
   Notion에 이미 올렸으면 D-4대로 거기서도 지운다.

## D. 세션 날 끝

1. **데이터 전달:** 저장 폴더(Windows `C:\Users\<이름>\StepMeter-human\`, Mac `/Users/<이름>/StepMeter-human/`)의 그날 `upload-<코드>.zip`을 팀 Notion의 팀원 전용 페이지에 올려 측정 지표 담당에게 넘긴다.
   공개 저장소, 이슈, 메신저(카톡 등)에는 올리지 않는다. 서버 업로드(`upload.py`)는 쓰지 않는다([ADR 0011](../docs/adr/0011-w3-plan-gaps.md) 4번).
   사이트 빌드 해시는 notes의 `site_manifest_hashes`에 들어 있다.
2. **커밋하지 않는다.** 수집 파일을 저장소 폴더로 옮겨 커밋하지 않는다. 저장 폴더를 OneDrive·iCloud처럼 동기화되는
   폴더(문서·바탕 화면)로 옮기지 않는다. 동기화되면 개인 클라우드에 사본이 생겨 4번 삭제로 다 지워지지 않는다.
3. **동의서 보관:** 서명한 동의서는 데이터와 분리해 보관한다. 사진을 찍거나 스캔해 올리지 않는다.
4. 보관 기한(2026-12-31)이 지나거나 참가자가 철회하면 진행자 PC와 Notion 페이지의 파일을 지우고 Notion 휴지통에서도 지운다.
   철회는 진행자 PC에서 C-8대로 지운다(코드를 다시 쓰지 않게 표시가 남는다).

## 문제가 생겼을 때

| 증상 | 할 일 |
|---|---|
| exe를 열자 "프로그램을 시작하지 못했습니다" 창이 뜬다 | zip을 새 폴더에 처음부터 다시 풀고 그 안의 exe를 연다. 그래도 같으면 창에 나온 로그 파일을 세션 운영 담당에게 보낸다 |
| 참가자가 그만두겠다고 한다 | C-8 |
| 시작 전 점검에서 "화면 높이"·"화면 너비" 실패 | A-3대로 배율을 바꾸고 [다시 점검] |
| "포트를 이미 다른 프로그램이 쓰고 있습니다" | 다른 StepMeter 창을 닫고 프로그램을 다시 연다 |
| "사이트 빌드" 실패 | 그날 세션을 열지 않고 세션 운영 담당에게 알린다 |
| 참가자 화면에 "문제가 생겼습니다. 진행자를 불러 주세요." | 페이지가 뜨기 전에 멈췄으면 [다시 띄우기]. 이미 봤으면 [이 페이지 건너뛰기] — 같은 페이지는 다시 하지 않는다 |
| 프로그램이 꺼졌다 | 다시 열고 같은 진행자·코드로 [다음]. 저장된 페이지는 건너뛰고, 진행 중이던 페이지는 다시 하지 않고 "기술 문제"로 남는다 |
| 참가자가 브라우저 창을 닫았다 | 미완료로 저장되었다. 다음 과업으로 넘어간다 |
| 검사 결과에 `*.invalid.json` | 지우지 말고 수집 스크립트 담당에게 알린다 |
