# 사람 실험 참가 동의서 (초안)

StepMeter 소요 시간 모델 보정을 위한 사람 데이터 수집에 쓸 동의서다. 참가자에게 보여주는 본문은 아래 구분선 다음부터이며, 그 위는 운영용 메모다.

- **근거:** 개발계획서 9.1 (수집 항목, 진행 조건), 서비스 기획서 개인정보 항목
- **담당:** 대시보드 UI (모집·동의서·세션 진행)
- **상태:** 초안. IRB 확인 결과와 아래 "결정이 필요한 사항"이 정리되면 확정한다.

# 리뷰어에게 묻는 것

> **이 동의서는 그대로 쓸 수 없는 상태다.** 본문에 채우지 않은 빈칸 `[ ]`이 4개 남아 있다. 완성본으로 보지 말 것.

| # | 누구에게 | 묻는 것 | 왜 급한지 |
|---|---|---|---|
| **1** | **PM** | 결정 필요 1번(**서명과 익명의 관계**)과 2번(**보관 종료일**)을 **IRB 문의에 함께 넣을 수 있는가** | **가장 급함.** 둘 다 IRB 담당의 답에 달려 있고, 보관 종료일이 비면 동의서를 인쇄할 수 없다 |
| 2 | PM | 결정 필요 3번(**사례 여부**)과 4번(**담당자 표기**) | 모집 공고와 같은 내용이어야 한다. 담당자 연락처는 레포에 채우지 않는다 |

## 운영 메모 (참가자에게 보여주지 않는다)

**진행 조건.** 외부 참가자 실험은 **2026년 11월 2일까지 학교 연구윤리(IRB) 담당에서 심의 면제 또는 심의 대상 아님을 확인받은 경우에만** 한다. 확인이 안 되면 팀원 데이터로 수집·보정 파이프라인이 동작하는지만 검증하고, 리포트와 발표에서 '사람 데이터로 보정'이라고 표현하지 않는다.

**이 레포에 올리지 않는 것.**

| 올리지 않는 것 | 이유 |
|---|---|
| 서명된 동의서 원본·사본·사진 | 서명은 개인을 식별한다. 레포가 public이다 |
| 참가자 이름, 학번, 연락처 | 개인정보. 수집 자체를 하지 않는다 |
| 참가자 코드와 사람을 잇는 표 | 이 표가 있으면 코드가 익명이 아니게 된다 |
| 아래 본문의 `[ ]` 자리에 채운 실제 담당자 이름·연락처 | 연락처는 커밋하지 않는다. 인쇄할 때만 채운다 |

**참가자 코드 규칙.** `P01`~`P15`를 순서대로 쓴다. 코드에 날짜·이니셜·학과 같은 추측 가능한 정보를 넣지 않는다. 세션이 끝나면 코드와 데이터 파일명만 맞춰 두고, 누가 어느 코드였는지는 기록하지 않는다.

**동의서 운영.** 종이로 받아 데이터와 분리해 보관한다. 철회 요청을 받으려면 요청자가 자기 코드를 알아야 하므로, 세션 끝에 **참가자에게 자기 코드를 알려 준다.**

**참가 조건 확인 (결정됨).** 조건은 "벤치마크 앱을 본 적 없는 사람"이다. 두 단계로 확인한다.

1. **모집 공고에 조건을 적는다** — 애초에 해당자만 신청하게 한다
2. **세션 시작 전에 구두로 한 번 묻는다** — "이 화면들을 전에 보신 적 있나요?"를 과업 설명보다 먼저 묻는다

공고만으로는 조건을 안 읽고 신청하는 사람을 막지 못하고, 구두 확인만으로는 이미 온 사람을 돌려보내게 된다. 12~15명을 모아야 하는 일정에서 헛걸음은 손실이 크다. 사전 설문은 응답 관리와 개인정보 설계가 추가로 필요해 쓰지 않는다.

조건에 맞지 않는 분이 오면 **그 자리에서 정중히 설명하고 데이터를 받지 않는다.** 숙련자 데이터는 보정 계수를 반대 방향으로 학습시키므로(9.1), 아깝다고 섞으면 안 된다. 구두 확인은 과업 설명 전에 해야 한다 — 설명을 들은 뒤에는 "본 적 있다"고 말하기 어려워진다.

# StepMeter 사용성 측정 연구 참가 동의서

## 1. 연구에 대해

이 연구는 사람이 웹 화면에서 과업을 할 때 걸리는 시간을 측정해, 자동 측정 도구(StepMeter)가 예측한 시간이 실제와 얼마나 다른지 확인하기 위한 것입니다. 학부 프로젝트 과제의 일부로 진행합니다.

- **연구 과제명:** StepMeter — 웹 사용성 자동 측정 도구
- **담당자:** [담당자 이름] / [소속]
- **문의:** [연락처]

## 2. 참여하면 무엇을 하나요

준비된 웹 페이지 6개에서 "계정을 만든다", "상품을 장바구니에 담는다" 같은 간단한 과업을 순서대로 해 주시면 됩니다.

- **소요 시간:** 20분을 넘지 않습니다.
- **잘하거나 빨리 할 필요가 없습니다.** 이 연구는 참가자의 능력을 평가하지 않습니다. 평소 하시는 대로 하시면 됩니다.
- 과업을 끝내지 못하셔도 괜찮습니다. 못 끝낸 것도 의미 있는 결과입니다.
- 쓰시는 페이지는 연구용으로 준비한 것이며, 실제 서비스가 아닙니다. 실제 가입이나 결제가 일어나지 않습니다.

## 3. 무엇을 기록하나요

과업을 하시는 동안 페이지에 넣은 스크립트가 아래를 기록합니다.

| 기록하는 것 | 설명 |
|---|---|
| 마우스 이동 | 화면 안에서의 위치와 시각 (초당 약 60번) |
| 누름·뗌·클릭 | 시각, 화면 안에서의 위치, 누른 대상 |
| 스크롤 | 시각과 이동량 |
| 키 입력 | 키를 누른 **시각과 글자 수만** |
| 입력 장치 | 마우스인지 트랙패드인지 |
| 화면 크기 | 브라우저 창의 가로·세로 크기 |
| 평소 컴퓨터 사용 시간 | 하루 대략 몇 시간인지 (직접 적어 주시는 항목) |

## 4. 기록하지 않는 것

아래는 **수집하지 않습니다.**

- **이름, 학번, 연락처, 생년월일** — 참가자 코드(예: `P01`)만 씁니다.
- **입력창에 적은 내용** — 어떤 글자를 쳤는지는 저장하지 않고 **글자 수만** 셉니다. 비밀번호나 이메일을 적어 넣으셔도 그 내용은 남지 않습니다.
- **화면 녹화, 사진, 음성** — 어떤 영상이나 음성도 촬영·녹음하지 않습니다.
- **연구용 페이지 밖의 활동** — 스크립트는 준비된 페이지 안에서만 동작합니다. 다른 탭, 다른 프로그램, 파일은 기록하지 않습니다.
- **마우스 위치는 브라우저 화면 안의 좌표만** 기록합니다. 화면 전체나 다른 창의 위치는 기록하지 않습니다.

## 5. 기록한 자료를 어디에 쓰나요

사람이 걸린 시간과 도구가 예측한 시간을 비교해, 예측식의 계수를 조정하는 데만 씁니다.

- 자료는 **참가자 코드로만** 다루며, 개인을 알아볼 수 있는 형태로 쓰지 않습니다.
- 과제 보고서와 발표에는 **여러 참가자를 합친 값**(평균, 중앙값 등)만 싣습니다. 개인별 기록을 그대로 싣지 않습니다.
- 자료는 연구팀만 봅니다. 팀 밖으로 넘기거나 공개하지 않습니다.
- **보관 기간:** [보관 종료일]까지 보관하고, 그 후 지웁니다.

## 6. 참여는 자유이고, 언제든 그만둘 수 있습니다

- 참여하지 않으셔도 아무런 불이익이 없습니다.
- 하는 중에 **이유를 말하지 않고** 그만두실 수 있습니다. 그만두신다고 말씀하시거나, 그냥 일어나셔도 됩니다.
- 그만두시면 그때까지의 기록을 지웁니다.
- 끝난 뒤에도 **자기 코드를 알려 주시면 자료를 지웁니다.** 코드는 세션이 끝날 때 알려 드립니다. 지우고 나면 되돌릴 수 없습니다.
- 이미 여러 사람을 합쳐 계산한 결과에서는 개인 자료를 되돌려 빼낼 수 없습니다. 이 점을 미리 알려 드립니다.

## 7. 위험과 이익

- 평소 웹을 쓰는 것과 같은 수준이며, 예상되는 위험은 없습니다. 오래 앉아 있어 불편하시면 중간에 쉬시거나 그만두실 수 있습니다.
- 참여로 직접 얻는 이익은 없습니다. [사례 여부]

## 결정이 필요한 사항

1. **서명과 익명의 관계** — 동의서에는 서명이 필요하지만 서명은 개인을 식별한다. 지금 초안은 종이 동의서를 데이터와 분리 보관하고 둘을 잇는 표를 만들지 않는 방식이다. IRB 담당이 다른 방식(구두 동의 기록, 코드만 적는 동의 등)을 요구하는지 확인해야 한다.
2. **보관 종료일** — 본문 5절의 `[보관 종료일]`. 과제 종료일(2026년 12월 20일) 직후로 할지, 성적 확정까지 둘지 정해야 한다. 날짜를 적지 않은 동의서는 쓸 수 없다.
3. **사례 여부** — 본문 7절의 `[사례 여부]`. 사례가 없으면 "참여에 대한 사례는 없습니다"로 적고, 있으면 무엇을 얼마나 주는지 적는다. 모집 공고와 같은 내용이어야 한다.
4. **담당자 표기** — 본문 1절에 누구 이름과 어떤 연락처를 쓸지. 개인 연락처 대신 팀 공용 주소를 쓸 수 있는지 확인한다. 어느 쪽이든 **레포에는 채우지 않는다.**

참가 조건 확인 방법은 위 운영 메모에서 정했다.

## 확정 전까지 남은 일

- 위 1~4번 정리 (1번은 IRB 확인 결과에 달려 있다)
- 모집 공고 문안 — 참가 조건을 명시하고, 동의서 2·3·7절과 내용이 어긋나지 않아야 한다
- 세션 진행 순서 메모 — 무엇을 어떤 순서로 말하고 보여줄지. 설명이 사람마다 달라지면 측정값도 흔들린다
- W2에 벤치마크 페이지 6개가 확정되면 본문 2절의 과업 예시를 실제 과업으로 바꾼다
