# worker/compare/

- **담당 역할:** 회귀 비교·인프라
- **하는 일:** 재측정 비교 로직, 기준 편차 기반 악화 판정, 경로 정렬.
- **참고:** 개발계획서 7.3~7.5

## W3 비교 v1

`GET /compare?base=<run id>&target=<run id>`는 기존 OpenAPI 형식으로 응답한다.
두 run의 소유권을 각각 확인하고 같은 과업·뷰포트의 completed run만 비교한다.
캐시는 같은 run 행을 정해진 순서로 잠근 뒤 upsert하며 호출마다 현재 이슈를 반영한다.

- 성공한 agent 시도의 측정값으로 중앙값·기준 편차를 계산한다. 성공 1회나
  기준 0에서 변화율을 정의할 수 없는 경우 `not_comparable`이다.
- 성공 2회면 `spread_weak=true`. agent 임계값은 동결 OpenAPI 설명대로
  `max(0.2, 기준 편차×2)`, 경계값과 같으면 악화가 아니다. 클릭 수는 +1 조건도 필요하다.
- full replay는 기준 대표 경로와 비교한다. 클릭 +1, 이동 거리·예상 시간 +10%가
  경계값을 포함한다. partial replay는 값이 있더라도 악화 판정을 만들지 않는다.
- 문제는 참고 목록을 제외하고 규칙·출처+경로·요소로 중복을 없앤다. 일반 대상은
  기존 matching 모듈을 쓰며 여러 후보가 있으면 임의로 짝짓지 않는다.
  axe R02/R10은 설명에 보존된 실제 selector를 쓴다. selector가 없을 때 행동 대상
  지문을 실제 axe 대상으로 대신 쓰지 않는다. 설명 생성과의 영구 연결은 협업 과제다.
- 경로는 대표 attempt의 행동 종류·역할·정규화한 이름으로 SequenceMatcher 정렬한다.
  이슈 신규/해결/유지, 지표 변화와 추가/삭제 단계를 함께 돌려준다.

W4 이력 누적 편차(pooled)와 재생기 구현은 이 변경에 포함되지 않는다.
검증: `tests.test_compare`, `tests.test_api`의 compare 계약·소유권·캐시 검사.
