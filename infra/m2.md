# W2 M2 로컬 실행 환경 (2026-11-08)

기준 main: ddc06c7, API·초대 코드 발급은 PR #32로 구현됐다.
Compose 기본 API 명령도 백엔드가 제공한 uvicorn 명령으로 연결했다.
`STEPMETER_API_COMMAND`는 다른 실행 설정이 필요한 경우에만 재정의한다.

## 지금 실행·검증할 수 있는 것

```sh
docker compose --profile m2 --profile test build api worker tests
docker compose --profile m2 up -d --wait api
docker compose --profile m2 run --rm api python -m infra.scripts.check_m2_api
docker compose --profile m2 run --rm worker python -m infra.scripts.check_m2_network
docker compose --profile test run --rm tests
```

- api/worker는 PostgreSQL 마이그레이션 성공과 Redis 준비 후 실행한다.
- API: 컨테이너 0.0.0.0:8000, 호스트 127.0.0.1:${API_PORT:-8000}.
- API 명령: `uvicorn apps.api.main:app --host 0.0.0.0 --port 8000`.
- 워커 대상 페이지: `http://m2-fixtures:8765/signup/index.html`. 내부 DNS이므로 호스트 localhost로 바꾸지 않는다.
- API와 워커가 `/app/data/screenshots` 볼륨을 공유한다. API는 실제 `/screenshots/{key}`로 제공한다.
- worker는 개발용 fake 모드이며 키를 전달하지 않는다. 실제 agent JOB_FUNC가 없으면 큐 소비 전에 종료한다.
- `test-db`·`test-redis`는 개발 데이터와 분리돼 있다. 전체 unittest를 개발 DB에 연결하지 않는다.
- 종료: `docker compose --profile m2 --profile test down`. 볼륨 삭제 옵션 -v는 사용하지 않는다.

`check_m2_api`는 실제 API를 호출해 아래를 검증한다.

1. 인증 없는 요청 401
2. 기존 관리자 명령으로 초대 코드 발급, DB에 sha256 지문 존재
3. 프로젝트·과업·측정 생성 및 OpenAPI 본문 검사
4. Redis runs 큐에 run-{id} 등록 및 queued 상태 조회
5. 미완료 리포트 409, 대기 중 취소 후 큐 제거·canceled 상태
6. 다른 초대 코드의 프로젝트에 접근하면 404
7. 공유 볼륨에 저장한 PNG를 API로 요청해 원문 바이트와 Content-Type 확인

초대 코드는 subprocess 출력에서 메모리로만 받아 콘솔·증거에 기록하지 않고 검사 종료 시 비활성화한다.
직접 사용하려면 `docker compose --profile m2 run --rm api python -m apps.api.issue_code "local E2E"`로 발급한다.
이 명령은 원문 코드를 한 번 출력하므로 공개 로그·PR·커밋에 붙이지 않는다.
`check_m2_network`는 실제 워커와 같은 컨테이너 환경에서 DB·Redis·브라우저·fixture·스크린샷 저장을 확인한다.

## 에이전트 구현 후 필요한 최종 확인

`worker.agent.run.run`과 Driver는 아직 main에 없다. 에이전트 담당의 #26 연결 후 다음을 실행한다.

```sh
docker compose --profile m2 up -d --wait api worker
export STEPMETER_API_URL=http://127.0.0.1:8000
export STEPMETER_E2E_SITE_URL=http://m2-fixtures:8765/
# STEPMETER_ACCESS_CODE는 발급한 코드를 환경 변수로만 설정
python -m unittest tests.e2e.test_m2_flow -v
```

실제 API→큐→워커→지표→리포트와 실행 중 취소·정리는 에이전트가 필요하다.
현재 대기 중 취소 검사와 이를 혼동하지 않는다. 테스트가 자체 실행하는 localhost fixture는 Docker 워커에서 닿지 않는다.
API healthcheck는 포트 열림 검사이며 응답 계약은 통합 검사로 확인한다.

## CI

Python job은 전용 Redis·PostgreSQL을 사용하고 변이 fixture·axe 예측·고정 SB Admin 변이도 재현한다.
Docker job은 실제 API 시작→API/큐/취소 검사→worker 컨테이너 네트워크 검사를 수행한다.
전체 M2 E2E는 코어 부재로 skip되며 이를 통과했다고 표현하지 않는다.

## 실제 M2를 건너뛰지 않는 엄격 실행 명령

```sh
docker compose --profile m2 up -d --wait api worker
docker compose --profile m2 run --rm api python -m infra.scripts.run_m2_e2e
```

이 명령은 agent JOB_FUNC를 먼저 import해 실제 구현을 확인한다. 없으면 exit 2로 중단하고
M2 통과로 표시하지 않는다. 구현이 있으면 기존 코드 발급 CLI로 임시 코드를 메모리에 받아
API 주소·컨테이너 내부 fixture 주소를 명시한 상태로 실제 tests/e2e를 실행한다.
종료 후 코드를 비활성화하며 원문 코드는 로그에 남기지 않는다. 결과는 공유 볼륨의 m2-e2e 폴더에 저장한다.
현재 #26의 코어·Driver는 별도 담당 작업으로 남아 있어 이 명령의 실제 측정 완료는 외부 의존성이다.
