# W2 벤치마크 잔여 상태 (2026-11-06)

기준: benchmark/selection.md, 앱 매니페스트, ADR 0003·0007·0008.
`conversion` 보조 페이지를 소스 앱 6개(최소 5개) 수에 포함하지 않는다.

| 개발 앱 | 현재 증거 | W2에서 남은 것 |
|---|---|---|
| sb-admin-2 | 로그인·가입 페이지 클리닝 패치와 W1 실행 증거 | 정상 동적 상태 PM 승인, 앱별 6종 변이·정답 교차 검토 |
| material-kit-react | 로그인·제품 페이지 클리닝 패치와 W1 실행 증거 | 대비 incomplete 수동 확인, 정상 동적 상태 승인, 6종 변이·정답 |
| shadcn-admin | 고정 커밋·출처·과업 선정 | 런타임·기준선 검증, 6종 변이·정답 |
| react-shopping-cart | 고정 커밋·출처·과업 선정 | 구형 빌드 도구·외부 데이터 정리 후 기준선, 6종 변이·정답 |

홀드아웃 2개는 비공개 장소에서 단독 관리하며 이름·설정·정답을 이 문서에 기록하지 않는다.
이번 작업에서는 홀드아웃 내용을 열거나 평가하지 않았다. 비공개 준비 완료 여부는 확인하지 않았으므로
소스 앱 준비 완료 숫자에 임의로 포함하지 않는다.
현재 공개 자료로 확인 가능한 W2 전체 기준선·6종 변이 완료 앱은 0개다.

팀 지침상 개발 앱별 제작은 리포트 UI·대시보드 UI·LLM/프롬프트·플랫폼 백엔드가 나눠 맡고
회귀 비교·인프라는 총괄, PM은 교차 검토한다. 현재 GitHub 열린 이슈에는 앱별 배정이 없다.
담당자 대신 정상 승인하거나 기존 pending 정답을 approved로 바꾸지 않았다.
기존 도구의 실행 방법은 w2.md를 따른다. 보조 페이지의 7개 케이스 검증과 앱별 준비 완료를 구분한다.

## 제안 GitHub 이슈 초안

제목: W2 개발 앱별 기준선·6종 변이 담당 배정 및 검토 일정 확정

받는 사람: PM·리포트 UI·대시보드 UI·LLM/프롬프트·플랫폼 백엔드

내용: W2 벤치마크는 목표 6앱/최소 5앱이고 보조 conversion fixture는 앱 수에 포함하지 않습니다.
공개 개발 앱 4개의 상태는 위 표와 같습니다. 각 앱 담당과 가입·구독 중심 과업,
기준선·결함 발현 증거 및 정답 제출 일정을 확정해 주세요. 기존 mutate.py·eval.py 형식을 재사용할 수 있습니다.
총괄 담당은 제출 증거·설정·정답을 취합하고 PM 교차 검토 후 평가합니다.
홀드아웃 작업은 별도 비공개로 유지합니다.
