# W3 개발 앱 평가와 회귀 자료

기준 main `2b02624`, ADR 0008–0011. 공개 개발 앱만 다룬다.
홀드아웃은 읽거나 실행하지 않는다. 생성물·DOM·로그·스크린샷은 git 제외다.

## 고정 과업

`tasks.json`은 4앱의 정상 8과업과 결함 24개를 정의한다. 과업 입력값은 가짜 값이다.
사람 실험 6페이지는 `human-study/pages.md`의 과업 문장과 같은 값을 쓴다.
`baseline-*`은 해당 앱의 baseline 빌드를 재사용한다. shadcn `baseline-users`는
추가 결함 정답을 만들지 않고 승인된 baseline의 빈 정답을 사용한다.

실행은 기존 API의 최소 반복 횟수에 맞춰 케이스별 3회(총 예정 96시도)다.
W3 0차 모델은 Haiku, W5 평가는 Sonnet이다. `mode=agent`로 실행하므로
미완성 replay를 완료한 것으로 세지 않는다.

## 준비와 실행

`infra/README.md`의 Python 3.12/Node 22 환경과 최신 수집 번들을 준비한다.
개발 앱은 `checkout.py`로 고정 커밋을 받은 뒤 각 앱을
`python -m benchmark.build_variant <app> <baseline|small|contrast|inert|overlay|below-fold|unnamed> --build`
로 빌드한다. 기존 폴더는 덮어쓰지 않는다. 실행기는 커밋·패치 해시·배포 엔트리를 검사한다.

평가용 PostgreSQL을 분리해 마이그레이션하고 `DATABASE_URL`로 지정한다.
실제 호출 키는 LLM 담당이 비공개 환경 변수 `ANTHROPIC_API_KEY`로 연결한다.
코드·JSON·명령 인자·이슈에 키를 적지 않는다. fake 모드로 정식 점수를 만들지 않는다.

```sh
export PLAYWRIGHT_BROWSERS_PATH="$PWD/.venv/ms-playwright"
python -m benchmark.run_development --preflight --output benchmark/evidence/w3/preflight-new
python -m benchmark.run_development --output benchmark/evidence/w3/run-new
python -m benchmark.score_development benchmark/evidence/w3/run-new
```

`--case shadcn-admin/baseline --case react-shopping-cart/baseline`처럼 일부부터 실행할 수 있다.
실제 평가 실행기는 API/RQ를 우회한 직접 워커+PostgreSQL 경로다. API/RQ 전체 연결은
별도의 M2 E2E로 검사하며, 실제 Claude+API/RQ 전체 검증이라고 표현하지 않는다.

실행 디렉터리는 항상 새 이름을 쓴다. 결과에는 모델·반복 수·비용·종료 사유·run id,
독립 확인 성공 수, 측정 자료, 특징 데이터, 빌드 출처와 행동 직전 DOM이 남는다.
API 기본 성공 조건으로 표현하기 어려운 체크박스·비밀번호 표시·상품 제거 등은
모델 성공 주장과 독립 DOM 검사 결과를 구분한다. 제거 과업은 카트에 상품이 있었던
중간 상태도 확인해야 성공이다. 미완료 케이스를 무검출 성공으로 바꾸지 않는다.

## 요소 일치와 채점 규약 v1

이 규약은 개발 앱에서 정하며 홀드아웃 평가가 끝날 때까지 유지한다.

1. 워커는 정답을 받지 않는다. 선택적인 EvidenceSink가 행동 직전 DOM과 실제 행동 대상,
   axe 노드의 식별자를 기록한다. 일시적인 메뉴가 닫힌 뒤의 DOM으로 대체하지 않는다.
2. 채점기만 승인 정답을 읽는다. 네트워크·스크립트를 차단한 복제 DOM에서 정답 CSS
   selector가 가리키는 요소와 실제 이슈 노드가 같거나, 그 요소가 노드를 포함하면 일치다.
   CSS 이름의 문자열 유사도로 정답을 맞히지 않는다.
3. 단위는 (케이스, 규칙, 실제 요소) 한 건이다. 3회 시도와 여러 step의 중복은 합친다.
   미일치 요소는 측정에서 만든 selector로 식별한다. 실제 대상을 모르면 별도 보고하고
   기본 목록에 포함된 해당 이슈를 맞힌 것으로 세지 않는다.
4. R01/R02/R03/R04/R06/R10만 채점한다. 다른 규칙은 별도 건수를 보고한다.
   `rules_only`는 step이 있는 경로 후보 전체, `scored`는 `is_reference=false` 기본 목록이다.
   현재 점수 튜닝 전 결과와 이후 점수 적용 결과를 같은 단위로 비교할 수 있다.
5. 실패·미실행 케이스는 제외 목록에 이유를 적고, 실제로 평가한 케이스 수를 명시한다.
   완료 결과가 하나도 없으면 점수는 null이다. 정상판 완주율의 분모에는 예정 시도 수도 남긴다.
6. 특징 추출은 실제 이슈 대상 식별자와 종료한 agent 시도 전체를 받는다. axe 대상이
   행동 대상과 다르면 행동 snapshot을 대신 주지 않는다. 정답·예측 점수는 입력하지 않는다.

axe selector의 영구 보관은 규칙·설명 담당과 합의가 필요하다. 이 실행 도구는
설명이 바뀌기 전에 얻은 live DOM selector를 별도 증거로 보존해 설명문 덮어쓰기에 의존하지 않는다.
베이스라인 담당자는 같은 규약의 입력으로 결과를 내보내야 하며 실행 자체는 해당 담당 업무다.

## 회귀 쌍 10개와 문구 변경 10개

`regression_cases.json`에 4개 개발 앱의 10개 시작 페이지·대상이 있다.
`regression_versions.py`는 고정 baseline 배포 산출물을 복사하고 동작 추가 JS를 주입한다.
원본 체크아웃·기존 빌드는 바꾸지 않는다. 소스 변이 24개와 구분되는 배포 버전이다.

- 회귀판: 원래 조작 전에 확인 dialog와 Continue 1회가 추가된다. pointerdown으로 열리는
  메뉴도 확인 전에 실행되지 않게 한다. 이후 원래 대상에 down/up/click을 한 번 전달한다.
  독립 기대값은 필요한 조작 +1회다. 이는 비교의 클릭 증가 사례이며 다른 결함 6종 정답으로 세지 않는다.
- 문구판: 대상의 역할·핸들러·목적지를 유지하고 이름만 바꾼다. 변경 문구는 매니페스트에 있다.
- 출처: 기준 커밋·패치 SHA256와 추가 JS SHA256을 `version.json`에 기록한다.

```sh
python -m benchmark.regression_versions --output benchmark/builds/w3-versions-new
python -m benchmark.verify_versions --builds benchmark/builds/w3-versions-new --output benchmark/evidence/w3/versions-new
```

브라우저 검증은 확인 전 원래 클릭 미전달, 확인 후 1회 전달, 문구 적용을 확인한다.
재생기 완주율 8/10이나 회귀 검출 9/10을 통과했다는 뜻은 아니다. 재생기 구현 후 이 버전으로
그 수치를 별도로 확인한다. W3 자료 제작과 W6 최종 회귀 검증을 구분한다.
