# W2 벤치마크 도구와 전환 과업

기준: 개발계획서 8장, ADR 0003·0007·0008. 이 문서는 구현 현황이며 팀 범위 변경 결정이 아니다.

## 재현

루트의 Python 3.12 가상환경·npm 의존성·Chromium·수집 번들을 준비한다(infra/README.md).

```sh
npm run build:collect
python -m benchmark.verify_conversion
python -m unittest tests.test_benchmark_eval -v
```

브라우저 실행 환경에 따라 `PLAYWRIGHT_BROWSERS_PATH="$PWD/.venv/ms-playwright"`를 설정한다.
검증기는 임시 loopback 서버를 직접 시작하고 종료한다. 외부 서버·API·결제는 사용하지 않는다.
수동 조작: `python -m http.server 8770 --bind 127.0.0.1 --directory benchmark/fixtures/conversion` 후 http://127.0.0.1:8770 에 접속한다.

## 과업과 성공 조건

| 과업 | 경로 | 성공 조건 |
|---|---|---|
| 무료 가입 | 쿠키 선택 → 이메일·8자 이상 비밀번호 → 가입 | `#result`가 `데모 가입 완료` |
| 구독 선택 | 쿠키 선택 → 열린 Shadow DOM의 Pro → 같은 출처 iframe의 확인 | iframe `#confirmation`에 `데모 구독 확인 완료` |

로그인·테스트 계정 저장 기능이 아니다(ADR 0004). 데이터는 페이지 메모리에만 있다.
쿠키 모달은 사용자 클릭으로만 닫는다. 정상 화면과 결함 화면을 새 페이지로 분리해 상태 누적을 막는다.

## 결함 설정

`mutations/conversion/*.yaml`은 YAML 1.2의 JSON 부분집합이다. `mutate.py`가 Playwright 페이지에 적용한다.
원본 파일은 바꾸지 않는다. 셀렉터가 정확히 하나를 가리키지 않으면 실패한다.

| 변이 | 실수 패턴 | 확인 근거 |
|---|---|---|
| small / R01 | 아이콘 툴바 크기 유틸리티 오용 | 인접 16×16 버튼 두 개, 중심 간격 24 미만 → WCAG 2.5.8 간격 예외 불충족 |
| contrast / R02 | 흰 배경에 밝은 글자 클래스 | #eee / #fff, 약 1.16:1; axe color-contrast 확인 |
| inert / R03 | submit 핸들러 연결 누락 | 유효한 입력 후 클릭해도 완료 문구 없음 |
| overlay / R04 | 로딩 레이어 제거 누락 | 중심점 hit test가 오버레이, snapshot.occluded=true |
| below-fold / R06 | 잘못 붙인 전체 화면 여백 | 1280×800 초기 화면 밖, 첫 화면 노출 false와 필요한 스크롤 값 |
| unnamed / R10 | 아이콘 교체 중 텍스트·이름 누락 | 빈 이름 버튼, axe button-name 확인 |

정상 1 + 변이 6을 실행해 DOM 계산값·스냅샷·axe 원시 결과·PNG를 `evidence/conversion/`에 보존한다(git 제외).
정상 화면의 모달 처리 직후 수동으로 정한 요소 5개 목록과 수집 결과를 비교하며 Shadow DOM/iframe context와 프레임 좌표를 확인한다.
이것은 합성 화면 검증이다. SPA 3개 스트레스 테스트 통과나 LLM 에이전트 완주율을 뜻하지 않는다.
다른 출처 iframe·닫힌 Shadow DOM·가상 스크롤은 이 화면에 포함하지 않았다.

## 정답과 평가

`labels/conversion.json`은 렌더링 확인 후 생성한 **PM 검토 대기** 정답이다.
PM은 실행 증거와 과업·규칙 대응을 검토한 뒤 review_status를 approved로 바꾼다.
규칙 작성자가 만든 예측을 정답으로 복사해서는 안 된다.

```sh
python -m benchmark.eval --labels benchmark/labels/conversion.json --predictions /tmp/predictions.json --output /tmp/evaluation.json
```

예측 형식: `{"split":"development","cases":{"baseline":[],"small":[{"rule":"R01","target":"#signup"}],...}}`.
모든 case를 명시하고 미탐지 케이스도 빈 배열로 넣는다. 키는 case·rule·안정적 target 세 개로 매칭한다.
같은 키의 중복 검출은 한 번으로 센다. 정상 화면의 검출은 FP다. 미검토 정답·누락 케이스·홀드아웃 입력은 거절한다.
정밀도·재현율·F1을 micro와 규칙별로 출력하며, 분모가 0인 값은 null이다.
이 형식은 벤치마크 내부 교환 형식이며 공용 API를 바꾸지 않는다. 실제 검출 결과의 target 정규화는 평가자가 수행해야 한다.
검증기는 정답과 같은 결과를 예측으로 만들어 성능을 주장하지 않는다.

## 11/8 마무리 변경

### R06 수정

`below-fold`는 이제 `entry.html`에서 시작한다. 과업은 "가입 시작 링크를 찾아 가입 폼을 연다"이고
그 페이지에는 `#signup` 링크 하나만 상호작용 대상이다. 쿠키 닫기·폼 입력 전에 첫 대상으로 클릭한다.
기존의 "이메일·비밀번호를 먼저 입력한 뒤 아래 가입 버튼 클릭"은 R06의 첫 대상 조건을 만족하지 않아 교체했다.
정상 진입 화면에서는 R06이 없고, 변이 화면에서 첫 대상으로 평가할 때만 R06이 나오는 것을 실제 수집 스냅샷으로 검사한다.
작업 중인 페이지·과업을 변경했으므로 기존 화면 증거 대신 이번 verification.json을 PM에게 전달한다.
정답은 pending을 유지하며 승인 없이 정식 점수를 계산하지 않는다. axe 베이스라인 경로도 같은 진입 화면으로 맞췄다.

### 실제 앱 소스 변이 빌드

React는 렌더링 후 DOM 변이가 사라질 수 있다. PR #34 작성자가 별도 브랜치에 만든 shadcn 소스 변이와
같은 방식으로 `build_variant.py`가 고정 커밋 → 기준선 패치 → 변이 패치를 별도 디렉터리에 재현한다.
원본 체크아웃은 수정·reset하지 않으며, 목적지가 존재하면 중단한다. 사용한 패치의 SHA256을 기록한다.
빌드 산출물은 benchmark/builds 아래 git/Docker context에서 제외한다.

```sh
python benchmark/checkout.py sb-admin-2  # 이미 있으면 다시 받지 않는다
for variant in baseline small contrast inert overlay below-fold unnamed; do
  python -m benchmark.build_variant sb-admin-2 "$variant"
done
python -m benchmark.verify_sb_admin
```

- SB Admin: 정상 로그인·가입 과업 2개, 등록 흐름 6종 변이의 발현·화면·axe 증거를 검증한다.
- SB Admin R06은 가입 과업의 첫 입력 대상 `#exampleFirstName`을 첫 화면 밖으로 이동한다.
- 작은 타겟은 등록 링크와 도움말 16px 두 개, 대비·무반응·가림·이름 누락은 등록 링크를 대상으로 한다.
- 사람 실험 초안의 로그인 Remember Me 작은 타겟과는 다른 과업이다. 실험용 변이로 임의 대체하지 않는다.
- 정답 후보는 labels/sb-admin-2.json에 pending으로 저장했다. 런타임 증거는 evidence/sb-admin-2/w2/에 있다.
- shadcn 패치가 main에 합쳐진 뒤에는 같은 도구로 `python -m benchmark.build_variant shadcn-admin <변이> --build` 가능.
- MUI는 해당 앱 소스 패치를 제공한 뒤 `--build`로 npm ci/build한다. shopping-cart도 현대화 기준선·package-lock.json·로컬 상품 데이터가 포함되어 npm ci/build로 재현한다.
- 라이선스와 upstream 소스는 각 격리 체크아웃에 유지한다.

## 개발 앱 3개와 비공개 2개 준비 완료 (추가 작업)

`material-kit-react`와 `react-shopping-cart`도 기준선·6종 **소스 패치**를 추가했다.
DOM 일회성 변경이 아니며 React 상태 변경 후에도 결함이 유지되는 것을 검사한다.

- MUI: 로그인 입력/비밀번호 표시, 제품 정렬/필터 과업. 장식 배경을 제거해 대비를 결정적으로 측정하고,
  필터 버튼 이름·대화상자 의미를 보강했다. 장식용 배경막은 투명하게 해 정상 배경 텍스트의 대비 오염을 막았다.
- 커머스: CRA4/node-sass를 Vite/Dart Sass로 교체하고 lockfile을 고정했다. 소형 결정적 상품 fixture와
  직접 작성한 로컬 SVG를 사용해 원격 JSON·이미지 요청을 제거했다. 검색/수량2 추가, 장바구니 삭제를 검증했다.
- 원래 소스·라이선스·고정 커밋은 유지한다. 외부 실제 계정·결제·메일은 사용하지 않는다.
- MUI·커머스 정상 과업과 변이의 결과를 `verify_material_kit.py`, `verify_shopping_cart.py`로 재현한다.

```sh
# 소스가 없는 경우에만, 매니페스트의 고정 커밋 받기
python benchmark/checkout.py material-kit-react react-shopping-cart
for app in material-kit-react react-shopping-cart; do
  for variant in baseline small contrast inert overlay below-fold unnamed; do
    python -m benchmark.build_variant "$app" "$variant" --build
  done
done
python -m benchmark.verify_material_kit
python -m benchmark.verify_shopping_cart
# 이미 생성된 디렉터리는 덮어쓰지 않는다. 기존 빌드의 패치 해시가 다르면 이전 빌드를 보존·이동하고 새로 준비한다.
```

모든 개발 앱을 조정하는 명령은 `python -m benchmark.verify_development --build`다.
소스 패치가 없는 앱은 제출 대기로 기록하고, 존재하는 앱은 고정 커밋·패치 해시와 렌더링을 검사한다.
`--build`가 없으면 네트워크 설치 없이 기존 빌드만 검증한다. 실패한 앱이 있으면 exit 1이다.
월요일 09:00 KST와 수동 실행용 `benchmark-development.yml`도 같은 명령을 사용한다.
이 워크플로는 **개발 앱의 준비·렌더링 검사**이며 StepMeter 정확도 평가가 아니다.
private manifest를 읽거나 홀드아웃을 CI에서 실행하지 않는다.

개발 앱 정답은 모두 pending이다. PM 승인 후 실제 검출 결과/axe 결과를 eval.py 형식으로 정규화해 채점한다.
현재 결과를 그대로 예측으로 복사해 정밀도·재현율을 주장하지 않는다.

홀드아웃은 사용자 위임으로 비공개 대체 2개를 준비했다. 이름·출처·고정 커밋·라이선스·기준선·12종 패치·정답·증거는
`benchmark/holdout/`에만 있으며 public 파일·CI artifact로 복사하지 않는다.
최종 검출 평가는 ADR 0008의 날짜에 1회 수행한다. 이번 확인은 독립적인 결함 발현 준비 검사다.

공개 개발 앱의 원본 MIT 고지는 licenses/에도 보존했다. 선정된 5앱 중 SPA 3개 조건도 확인했다.

## 11/9 main 병합 시 정리

- 기본 small.patch는 사람 실험용 로그인 Remember Me 변이를 사용한다. 이전 등록 버튼 변이는 small-register.patch에 보존하며 기본 6종 집계에 포함하지 않는다.
- 검증기는 로그인 체크박스의 실제 label/의사요소 클릭 영역과 간격을 기준선과 비교한다. 정답 대상은 #customCheck다.
- R06은 최신 main의 click 행동 기준을 따른다. 첫 대상 여부로 제외하지 않고 type은 제외한다. 입력 필드 변이는 스크롤 후 실제 click을 수행한다.
- conversion은 main의 승인된 가입 경로·정답·검증기를 사용한다. entry.html 실험은 기본 변이에서 사용하지 않는다.
- Docker에는 양쪽의 build_variant·LLM/axe·SPA·사람 수집 모듈과 git을 모두 포함한다.
- shadcn 소스 패치와 정답은 이제 main에 들어왔으며, 여기의 기존 제출 대기 설명은 병합 전 작업 기록이다.
